# 邮箱总路由

本 skill 只负责路由与跨邮箱边界控制，不直接读取配置、连接邮箱或调用收发脚本。

## 路由规则

- 用户要求初始化配置、保存账号/密码/授权信息、检查配置、测试登录或排查认证/连接错误时，使用 `$email-onboarding`。
- 用户明确提及腾讯企业邮箱、企业微信邮箱、`exmail.qq.com` 或企业邮箱域名时，使用 `$tencent-exmail`。
- 用户明确提及 QQ 邮箱、`@qq.com`、`@foxmail.com` 或 QQ 邮箱授权码时，使用 `$qqmail`。
- 用户明确提及 Gmail、Google Mail、`@gmail.com` 或 Google 授权时，使用 `$gmail`。
- 用户只说“查邮件”“发邮件”而未说明服务商时：如果紧邻的上一轮已明确完成或正在进行某一服务商的邮箱任务，默认沿用该服务商，并在执行前简短说明“沿用上一轮的 <服务商>”；否则先询问要使用腾讯企业邮箱、QQ 邮箱还是 Gmail。不得从邮箱地址、历史偏好或配置文件猜测默认账户。

## 工作方式

1. 先确认服务商、账户范围、操作类型和结果范围。只有同一会话紧邻上一轮明确的服务商可以作为默认值；用户随时可以指定其他服务商覆盖该默认值。
2. 读取对应服务商 skill 的 `SKILL.md`，并完全遵循其认证、工作区、授权和异常处理流程。
3. 用户要求跨多个服务商时，为每个服务商创建独立任务工作区；不得复制或混用凭据、规则、附件与日志。
4. 只有在用户明确要求合并时，才汇总多个服务商的结果；合并结果必须标明服务商与来源工作区。

## 边界

- 不从自然语言、历史记录或邮箱地址推测用户拥有哪个账户。
- 不将 Gmail 的 OAuth 令牌、QQ 邮箱授权码和腾讯企业邮箱密码写入同一配置文件。
- QQ 邮箱与 Gmail 均有独立可执行子 skill；必须按已确认的服务商路由，不得伪造、混用或改用其他服务商连接器。
