# 中断诊断

## 可以确定的情况

- `complete`：任务正常完成并写入结束事件。
- `failed`：执行过程捕获到错误；查看 `error_kind`、`reason` 和退出码。
- `waiting_user`：任务在等待用户提供信息、确认或权限。
- `cancelled`：用户或调用方明确取消。
- `interrupted`：执行器捕获到键盘中断或终止信号。

## 只能推断的情况

状态长期停留在 `running`，说明最后一次检查点之后没有机会写入结束事件。常见原因包括模型或宿主进程退出、系统休眠、终端被关闭、资源耗尽、工具进程被强杀、硬性超时或上下文截断。

仅凭过期的 `running` 状态不能区分上述原因。应结合宿主日志、模型服务日志、系统事件、内存/显存记录和上下文用量信息进一步判断。诊断工具会明确标注为推断，不会把它报告成已确认的上下文限制。

## 建议排查顺序

1. 查看 `status.json` 的 `phase`、`reason`、`next_action` 和 `updated_at`。
2. 查看 `events.jsonl` 的最后一个成功检查点。
3. 若存在退出码，优先按程序错误处理。
4. 若没有退出码且状态过期，检查本地模型服务、宿主和系统日志。
5. 若上下文接近上限，应从 `next_action` 继续新一轮任务，而不是从头重做。
